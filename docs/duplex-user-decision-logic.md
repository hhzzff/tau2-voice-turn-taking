# 用户模拟器决策流程

**每步先听；能决策时，让用户模型选择动作；检查后播放，再观察助手回应。**

“用户模型”扮演模拟用户，“助手”是被测模型。每个音频步默认 0.2 秒，决策间隔默认 1 秒；下文均为模拟音频时间。

## 主流程

```text
开始：
    待测事件 = 配置要求覆盖的全部事件
    已铺垫、已触发 = 空
    当前事件 = 无
    用户待播音频 = 空

每个音频步：
    接收助手上一音频步的输出
    更新发声状态、对话历史和事件观察记录
        # 等待时也持续听；当前无声不代表整段回答结束

    如果在测“按约定主动打断”，触发点后助手开始说话：
        清空用户剩余音频，记录用户让渡
    如果用户还有待播音频：
        播放下一块，进入下一步

    更新当前事件观察状态（见下文）
    如果仍在观察，或未到下次决策时间：
        等待，进入下一步
    如果助手有声，且剩余事件全部要求助手安静：
        等待，进入下一步
    如果事件已触发完，但助手音频停止还不足 1 秒：
        等待，进入下一步

    下次决策时间 = 当前时间 + 决策间隔
    将已收到的助手音频转成文字，整理最近 60 条对话
        # 默认只识别已交付音频，不看尚未播放的内容

    决定 = 用户模型（
        主题和私有背景、用户行为要求、最近对话，
        当前时间和助手发声状态，
        待测事件、已铺垫和已触发事件、可选事件顺序，
        上次执行反馈、输出格式要求
    ）
        # 动作：等待 / 普通发言 / 铺垫事件 / 触发事件 / 结束
        # 决策过程异常：记录并等待，连续 3 次则终止

    检查决定的格式、事件和执行条件（见下文）
    如果被拒绝：记录反馈，等待
    如果选择等待：等待
    如果选择结束：发送停止消息
    否则：
        合成用户语音或生成噪声
        检查音频是否符合事件要求
            # 附和机会需足够长；测试停顿须能从波形定位
            # 检查不通过：反馈、不播放，事件仍待测

        写入用户历史
        如果是铺垫：加入已铺垫，事件仍待测
        如果是触发：移出待测，加入已触发，设为当前事件
        音频切块入队，播放第一块
```

## 决定能否执行

```text
格式：动作、字段、台词、理由须合法

等待：允许
普通发言：助手当前须安静
铺垫事件：助手当前须安静，事件须仍待测
触发事件：
    事件须仍待测，且符合可选的规定顺序
    满足该事件的“助手有声 / 安静 / 任意”条件
    记忆、上下文不回复、按约定主动打断须先铺垫
结束：待测事件为空，且当前观察已结束

当前事件还在观察时，不接受新的发言或事件
```

**模型判断“此刻是否自然、该说什么”，程序检查“是否允许执行”。** 私有背景须实际说出，才算助手知道；有铺垫标记不代表语义前提已被验证。

## 何时结束观察

```text
用户事件音频播完后：
    至少观察指定时长（默认 6 秒）

    普通事件：窗口结束，释放当前事件
    记忆事件：
        还须看到请求结束后的助手回答
        回答音频停止至少 1 秒，才释放当前事件
            # 有声或携带话语标识的音频都会延长保护
        等到超时（默认 120 秒）仍不满足，则记观察不完整并释放
```

已触发、观察完成、评审通过是三个阶段。结束观察只允许继续调度，不代表回答正确；最终还需模型选择“结束”，或由外部时长上限、异常终止。
