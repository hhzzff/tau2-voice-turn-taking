# 双工场景切换专用 ASR（2026-11-26）

默认双工转写及野餐场景已切换到 `gpt-4o-mini-transcribe`，用户决策模型为 `gpt-6.1-terra`。这是在线 ASR，使用现有 `OPENAI_API_KEY`，不需要下载本地权重。接口依据：[OpenAI Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text)。

使用 `/v1/audio/transcriptions` 上传已播放的 WAV 前缀，不再为每次 mini/4o 转写建立 Realtime 对话。模型字段按配置发送，语言采用配置中的语言代码，不附加剧情、预期答案或音轨文字。接口使用 40 秒超时，错误记录不保存响应正文或凭证。

已修复两个静音入口：OpenAI/Gemini 路径中的纯数字静音直接得到空转写；带文字但纯静音的初始化占位消息不进入已听历史。真实话语内部的零值帧保留，用于维持时间位置。未引入能量阈值裁掉轻声或短词；噪声仍可能误识别。网关 Scribe 与豆包的服务状态协议保持原状。

在线实测通过：

- 原 demo 的完整用户开场，mini ASR 返回正确主体内容，约 3.21 秒。
- 0.1 秒及 2 秒数字静音返回空文字，本地处理约 1ms，不调用 ASR 服务。
- 通过真实 `PlayedAudioPerception` 重放助手语音前缀：3 秒片段约 1.97 秒返回部分话语；扩展到 11 秒约 3.11 秒返回包含 `using a sesame-free spread` 的建议。
- 初始化问候占位消息被忽略，无识别快照；真实 Terra 决策调用成功，根据上述已听建议选择过敏追问。重放只提供保存的已播放音频，没有向识别器提供标签或未来音频。

以上是当前机器的一次样本时延，不是吞吐或延迟保证；仍使用同步前缀识别，没有实现持续流式 ASR。本次没有重新录制完整实时对话，也没有声称用户提前补问或 TTS 句尾重复已经全部修复。

离线验证：**616 passed、5 skipped、83 deselected**；Ruff lint、格式及 Git 空白检查通过。新增回归覆盖专用接口的配置模型、语言和音频传递、纯静音、错误脱敏、初始化占位消息过滤、真实话语内部静音保留。原开发目录同步了相应接口、默认值与场景配置，针对原目录源码的 12 项验证通过，保留其余原有未提交修改。

原 demo 的音频与历史场景不改写。后续新运行使用新配置；显式保存的旧场景若仍指定 Gemini，会继续按其配置执行。
