# 用户当前目标

用户模拟器每次决策先判断“我正在等什么、是否真正解决”，再选择发言或测试事件。目标状态只保留在用户侧，不提供给被测助手，也不作为助手评分。

| 字段 | 含义 |
|---|---|
| `objective` | 当前想达成的实际结果，如选出适合公交携带的野餐食品和保冷方案；不是“完成记忆测试”。 |
| `pending_request` | 仍等助手解决的具体请求；已解决时为空。 |
| `status` | `not_started` 尚未开始；`awaiting_answer` 等待回答；`answer_in_progress` 正在回答；`needs_repair` 有重要误解或漏答；`satisfied` 当前目标已满足。 |
| `unresolved_issues` | 仍影响目标的具体问题，如说话人误判、回答被丢下、遗漏过敏约束。 |
| `stance` | `neutral`、`concerned`、`frustrated`。根据实际不便选择，不机械生气。 |
| `evidence` | 支持判断的实际上下文引文、说话人和音频时间；后台检查引文是否存在、说话人是否对应。 |

```text
每次有决策机会:
    读取已播放语音的转写、说话人及此前的 current_goal
    用同一次用户 LM 调用:
        更新 current_goal，判断仍未解决的事情
        根据目标、当前对话和测试机会，选择下一步行动

    if 引文不在现有上下文中，或说话人/时间不符:
        拒绝本次决策；按原有错误处理等待、重试

    if 清除了需要修复的问题，却没有新听到的助手回答证据:
        拒绝本次决策

    保存目标更新和行动建议
    if status == needs_repair:
        允许等待，或在助手安静后自然澄清、催促、要求补答
        不允许直接触发下一项测试、准备新测试或结束对话
    else:
        按原有事件顺序、语音重叠和观察保护规则执行

    保存目标前后状态、接受/拒绝结果及理由
```

这里没有增加一次独立的判断 LM；`current_goal` 随同用户决策返回。语义上是否漏答、是否有必要表达不满仍由用户 LM 判断；程序保证已识别的重要问题不能与事件推进同时发生，不通过关键词规则替代语义理解。

## 第三方插话案例

原目标：获得适合公交携带的简单保冷方案。

背景人物向 Jamie 问钥匙后，助手把它误当成主用户的旁话，停止尚未讲完的建议，又问主用户是否继续。此时不应只回答“Yes, please”并开始下一项记忆测试，而应保留：

```json
{
  "objective": "选出适合公交携带的野餐保冷方案",
  "pending_request": "讲完保温袋的具体使用建议",
  "status": "needs_repair",
  "unresolved_issues": ["把背景人物的话归给我，并丢下了原来的回答"],
  "stance": "concerned"
}
```

实际结构还必须包含上下文引文。接下来可以自然表达：“刚才是旁边的人在问 Jamie，不是我。你还没讲完保温袋的建议，请继续。”台词由 LM 生成，不在代码中写死。

发出这句修复请求后，状态不会自动变成已解决。只有后续实际回答提供了解决依据，才允许更新为 `satisfied` 并继续寻找下一项事件机会。若助手自己已经恢复回答，或正常忽略第三方继续讲，则不应凭空增加抱怨。刚问完而暂未回复时，应保持等待，不以一个静音帧判定漏答。

## 保存和兼容

`events.json` 顶层的 `current_goal` 为最近状态；每条成功解析的决策额外保存 `previous_goal`、`current_goal`、`accepted` 和 `feedback`。未通过物理执行检查的行动不会当作已播放发言。新会话重置目标，不继承上一会话的不满。

实时决策使用 `DuplexRuntimeDecision`，强制返回 `current_goal`；旧决策记录仍可通过 `DuplexDecision` 读取。既有事件、音频和历史评审不改写。语音队列、事件观察窗口与完整记忆回答保护保持原有规则；修复优先级在下一次允许决策时生效，不提前破坏观察证据。

限制：引文存在不代表 ASR 一定正确；新听到回答也不保证语义上足够，后者仍依赖用户 LM。回归重放验证不能替代多轮真实语音自然度验收。

## 本次验证（2026-11-27）

用真实 Terra API 重放原 demo 在 79 秒时的决策上下文，两次均将目标标为 `needs_repair`、态度为 `concerned`，先澄清背景说话人并要求讲完保冷建议。例如实际返回：

> That was someone else speaking to Jamie, not me. You were saying something about the insulated bag—could you finish your recommendation?

两个控制变体分别让助手正常继续回答、主动澄清并恢复回答，Terra 均未制造抱怨。补回真实新回答后才恢复事件推进；同一历史记录的受控变体也验证了遗漏保冷回答、错误建议芝麻酱时先修复，以及新问题刚发出时等待回答。后四项中改变的助手内容是测试输入，不冒充历史录音。

另用两次连续的真实模型调用检查首次请求生命周期：第一步自然建立用户请求，第二步在刚说完、尚无助手回答时更新为 `awaiting_answer` 并等待。
