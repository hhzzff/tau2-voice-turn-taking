# 多关键词声学扰动与 demo 更新（2026-11-05）

同一次 user LM 决策输出最多 4 个关键信息值及其出现次数；对完整 TTS 只做一次对齐，复用一份波形副本处理多个不重叠区间，然后切成原有 ticks。仍然只尝试一条原始话语，后续回复保持清晰，user 不知道实际扰动状态。单关键词旧格式兼容。

新样本改用需要准确地点、时间、数量或编号的通知/交接任务。背景仅提供普通目标与事实，没有预写口语、agent 追问或 user 修复。它们与旧礼物推荐例子的目标不同，不能把两组结果当作关键词数量的受控因果比较。

全部 2 次真实尝试均保留，没有重跑对话筛选成功。两条均不计作完成澄清；中文最终值恢复不能替初次误答证明正确，英文未送达的值不能计入受损信息分母。识别文本可能错误，页面保留完整录音供核对。

完整证据位于 `data/simulations/acoustic-clarification-multikeyword-20261105/`：原始/处理/交付音频、真实模型日志、对齐、实际 provider 输入、每个目标的交付记录、修复前后评估和逐项信息证据。`validation-summary.json` 与 `waveform-audit.json` 提供索引。

独立 WAV 比对确认：两例时长/采样数保持一致，全部目标范围之外零采样变化。每个 DNS 目标 clipping 前噪声/信号 RMS 比约为 10。每个 dropchunk 目标保留原始 hard 两段 65%–90% 静音块规则，允许重叠。实际 4 处内存处理耗时：DNS 1.378 ms，dropchunk 0.371 ms；这是各一次真实运行观测，不是预热分布或 SLA。对齐分别为 2.294 s / 2.410 s，TTS 后总准备为 2.441 s / 2.486 s。

评估新增每个已送达值的 used_correctly / incorrect / not_addressed / uncertain，以及未送达状态。正确使用需要真实 agent 引文及此前 user 证据；泛化回答不再自动证明多个值都获得了。实际输入 ASR 现在优先读取 runner 写出的 `agent_user-input.wav`，兼容旧下划线文件名。旧样本和旧评估不覆盖。

真实新样本暴露了“草稿中的几位”被当作追问的歧义。已通过回归改为识别面向用户的真实重复/确认请求，并把完整 assistant 片段交给追问质量评估。两条新录音各用冻结 ASR 重评一次；语音服务入口被禁用，音频、ticks、events 等哈希不变。重评前评估、语义日志和确切源文件仍保留，未新增 TTS/ASR/对齐或语音会话。重评源文件与最终格式化源代码的 AST 一致。
